| US-36, US-39 Replay decoding | The movement files are Parquet compressed with zstd, and their columns are «defined by Te Tengo Captura», which has not written them down yet. zstd alone can be read in pure Dart on every target (`archive` 4.x `ZstdDecoder`). There is no reliable Parquet reader for Dart: `dartframe`'s reader is a placeholder, `libbigdata` is native only, and `dart_duckdb` on the web means shipping duckdb-wasm. So the app **does not decode**: the player, the timeline, the events, the stretches without data, the logging and the body-points switch work, and the stage says «Esta versión aún no dibuja los movimientos» / «No disponibles: esta versión aún no puede dibujarlos.» The still frame of the last event (decided: opening the camera shows it and is not logged, CA-39.3) would come from the clip's landmarks (`GET /api/alertas/{id}/clip` → `puntos`), the cheapest source that creates no replay, and needs the same decoder; until then the stage shows the phase from the alerts («Posible caída») and no skeleton. The code is ready behind `DecodificadorMovimientos` (download and `sha256` check in `FuenteFotogramas`, drawing in `PintorEsqueleto`, tested with a fake decoder). Options: (1) the API converts each file to a compact JSON or binary replay format; (2) the PC uploads that lightweight format next to the Parquet file, with a contract field for its URL; (3) a minimal pure-Dart Parquet reader for one pinned schema (PLAIN encoding, no dictionary, page v1, zstd through `archive`) once the agent contract fixes the columns; (4) parquet-wasm or duckdb-wasm on the web and a native library on the phones (heavy). (1) or (2) is recommended | Team (format) | 2026-10-11 |
